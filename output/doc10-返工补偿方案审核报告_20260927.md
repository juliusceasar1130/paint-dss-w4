## 二、问题 ①：事实修正与数学建模是否完备严密

**事实修正：完备**。v1.0 的三处纠偏（22IS005 已豁免、真正漏网点、25IS110 末端）全部数据支撑，且双峰"双向错配"定性比 v1.0"系统性偏大"准确得多（8/12 项命中，方向与量级皆实）。

**数学模型：方向正确，4 个严密性缺口**：

ΔT(s,m) = P(fut|s,m) × E[T_rem − T_baseline | fut=1] + 基线修正项

- **缺口 A（必须定义）：基线修正项**。无偏性要求 E[T_rem|fut=0] = baseline。但 baseline 取干净组 **P50**，而干净组自身有肥右尾（实测 22IS340 永洁组：P50 19.9h vs 均值 45.2h，P90 96h；01IS205 ALL：偏差 +8.6h）。故必须定义：
  `基线修正项(s,m) = mean(rem_clean) − p50(rem_clean)`（同人群过滤），22IS340/YM33J- 达 **+25.3h**——漏掉它，delay_mean 会系统性低估约 25h（该站）。建议只进 delay_mean_s，不进 delay_p50_s。
- **缺口 B（必须做敏感性）：极端肥尾下均值脆弱**。22IS340 返工组均值 116.5h（P90 = 233h），个别 10 天滞留车会拉动 delay_mean 分钟级。阶段 0 预演须同出 **mean / 截尾均值（P5~P95 winzorize）/ p50 三列**，按稳定性（n_fut≥30 且变异系数）逐站选列，并把选择结果留档。
- **缺口 C（建议 v1 简化）：P(fut) 与 diff 学习窗不匹配**。P(fut) 用滚动 8 周（v2_future_flag），diff 用全窗；返工率月度双峰（04 23.5%/06 10.8%/07 23.1%/09 15.5%），两窗混用引入季节错配。建议 v1 表统一用 ⑥a 全窗 P(fut)（与 diff 同源）；周度化留作后续增强（W2.1 已证明周度 p 价值，但交互复杂度 v1 不背）。
- **缺口 D（口径一致）：diff 必须对引擎实际消费的基线学习**。引擎 `base = resolve_cohort_p50(...) or resolve_main(...)`——若 cohort 混合基线可用，diff 应对 cohort 基线（或其按 cohort 分行）学习，否则残留 P(fut)×(base_cohort − base_main) 量级的残差（分钟级~小时级，量小但应成文）。
- **边界（必须写进文档）：p≥0.5 站的单车误差有结构性下界**。标量（无论取何分位数）无法同时摆对两簇：22IS340 永洁组必被高估 ≈ delay_p50、返工组必被低估 ≈ (1−p)×Δ。该处 delay_p50 列的语义 = **返工轨迹条件 ETA**（68.9h 簇中心），单车看板解释文案需按此写。真正的单车修复在第二迭代（SCC 切环后 flag 分支 + 环类型条件化），文档应明示第一迭代不承诺 p≥0.5 站的单车精度。

## 三、问题 ②：双列维表与三级退化树

**双列设计：合理，通过**（mean 供聚合加法无偏、p50 供单车抗离群——职责划分正确；表量级 ~车型×站 ≤ 6k 行，无工程问题；BIGINT 秒合理）。附加要求 = 上节缺口 A/B/D 落地 + p50 列在 p≥0.5 站的语义注释（数据字典写清楚）。

**三级退化树：框架通过，3 个 spec 缺口**：
1. **"车型大类"未定义**——需给出具体规则（建议：body_type 前缀 2 字符 / 平台映射表，落 `dss` 维表或常量），否则实现歧义。
2. **N≥30 门槛须双人群**：干净基线 n 与 fut=1 差分 n 各 ≥30（22IS005 案例正是干净 n=5；fut 人群在稀有车型×站同样可能 <30）。
3. **末级兜底 = 0 需配监控**：缺行回退 0 会把"有返修但无表"的站变成纯低估。建议：回退 0 可接受（旧补偿本身有双算项，见 2026-09-26 复核），但回归跑数须输出**表覆盖率报告**（缺行站×车型清单 + 其中 p1≥0.1 的格子单独告警）；全局回滚已由 `DSS_USE_NET_DELAY=0` 覆盖。

**额外收益（建议写入验收）**：22IS005 / L3ACC11IS02 / 22IS625 三个 p≈0.99 的**已豁免**站，当前生产行为 = 豁免置 0 + 脏/回退基线 → 均值低估 **−64h ~ −113h**（2026-09-27 实测，学习窗 pre-fut 人群：22IS005 基线 2.6h vs 真值 115.3h → −112.7h；L3ACC11IS02 ALL 回退基线 4.1h vs 真值 107.5h(n=175) → −103.4h；22IS625 ALL 回退基线 4.4h vs 真值 68.5h(n=1329) → −64.1h），为现网最严重点。新表恰好根治（22IS005：0.993×(115.8−2.6)≈112.6h → ETA≈115h ≈ 真值 115.3h，近乎完美；22IS625 同理 ≈ 68.6h vs 68.5h）。**阶段 0 预演应把这 3 个已豁免站纳入对拍**（作为正收益证据），而非只看 3 个漏网站。

## 四、问题 ③：两迭代路线与止血节奏；盲点

**节奏判定：合理**。止血(30min) → 阶段 0 只读预演(0.5d) → W3 主线不阻塞 → 合流(1d) → 内网 5 天验收，顺序正确；"图资产是第二迭代增强而非阻塞前置"的判断正确（SCC 资产已在 `topology/`，概念已验证：75 站大 SCC 恰覆盖 13IS/14IS/22IS/L3ACC 返修区）；`DSS_USE_NET_DELAY` 符合项目 env 规范（2026-09-22 拍板）；"不虚高承诺 ≤20%，以阶段 0 实测定门"是正确认识论。W3 `predictor.py` 走 `eta_v2.estimate_event`，delay 表**自动覆盖 W2/W3**（含 α 缩放，合理）。

### 必须修改的问题

**P0：验收门禁 1 与方案自身模型自相矛盾（文档最大问题）**
- 门禁 1："漏网站预测延误从 +21.2h/+12h 压降至 < 1.5h"。但按文档自己的公式，新表在 22IS340 应产生 **delay_p50 ≈ +49h / delay_mean ≈ +51~77h**（22IS340 返工簇占 54%，混合 P50 落在返工簇），L3ACC ≈ +22~45h，22IS520 ≈ +13~23h——**没有一列能到 <1.5h**。
- <1.5h 只在"豁免生效"解释下成立——而豁免恰恰是**方向性代价**：22IS340 p=0.53>0.5，旧补偿 21.2h 本是对返工多数派的**部分覆盖**（当前均值误差 −43h），豁免后均值误差扩大到 **−64h**（实测数据：base 19.6h vs 真值均值 83.9h）；L3ACC（p=0.30）−26h→−38h；22IS520 −19h→−27h。W2 5h 门不受影响（这些站距出口 ≥12.8h，5h 锚点车辆本不计入当前班次），但 W3 滚动预测与单车均值变差。W2 既有 A/B 记录（⑥b 净效果 −0.44pp，豁免整体轻微负向）与此一致。
- **门禁 1 改写建议**（按阶段 0 预演实测定值）：
  - (a) W3/W2 均值口径：三站 `mean(ETA−actual)` 绝对值相对基线**下降** ≥ X（22IS340 从 −43h 改善到 ≤−15h 量级，由预演定）；
  - (b) W1 单车口径：三站逐车符号中位误差相对当前模型**改善**（22IS340 当前 −28h 量级）；
  - (c) 永洁组高估（+20.9h 类"穿帮"）：对 p<0.5 站（L3ACC/22IS520）以 delay_p50 口径收敛；对 p≥0.5 站**明示不可消除**（双峰下界），改为"返工组低估收窄"。
  - 同时把"豁免止血"与"新表"的关系写成：豁免是**过渡态**，新表上线后对 flag=0 路径**取代**豁免（优先级成文：flag=1/2 → 环分支不变；flag=0 → base + delay，`DSS_USE_NET_DELAY=1` 时不再走 p×L1，comp_excl 仅对旧路径生效）。

**P1：止血步骤的方向性代价未披露**
步骤 ①（三站入豁免表）可执行（5h 门中性、UX 止血、1 天内被新表取代），但文档"30 分钟无代码风险止血"的表述应补一句：对 p>0.5 站（22IS340）豁免以扩大均值低估为代价，属过渡态，新表合流日即被取代。

**P2：文档需补的三处定义**（缺口 A 基线修正项公式 / 车型大类规则 / 双人群 N 门槛）——缺一即实现歧义。

### 其他盲点（建议采纳，非阻断）

1. **第一迭代不触碰 flag=1/2 环通路** → 返工车组 W2 误差（+73.16%）主体在此路径，第一迭代验收**不应承诺返工组改善**；内网 5 天验收按 docs/01 惯例返工组单独跟踪。
2. **曾考虑的低成本 quick-win 已实测排除**：对末端 p=0 站（25IS110/32IS/35IS）把 flag=1 改走主线基线——实测 loop_rem@25IS110 f1 = 3.2h vs 干净 12.8h，两人群不同（在环车辆走更快路径出环），**不是**简单"出环后主线"，不能这么改。第二迭代 SCC 切环是唯一正解（维持文档原判）。
3. **W3 α 与新表的交互**：`rem/α` 会连带缩放 delay（合理），但 M9 影子回放的 9.79% 基线须在 `DSS_USE_NET_DELAY=1` 下重跑确认无双重修正（α 自适应本身可能吸收部分 delay 偏差）。
4. **门禁 3 基线措辞**：8.08%（W2.1 引擎，KW36/37 场景 3）与 9.79%（W3 影子引擎 α=off）是**两个引擎**的数字，建议并列标注引擎，避免关账时混用。
5. **阶段 0 预演范围建议扩展**为三向对比 × 三列统计 × 6 站：{旧 p×L1 / 豁免 / 新表} × {mean / 截尾 / p50} × {22IS005, 22IS340, 22IS520, L3ACC21IS02, L3ACC11IS02, 22IS625}，输出：三站+3 豁免站的 mean/中位误差、YM33J- 门值预测（对照 W2 敏感性分析：YM33J- 完全准确 → 全厂 13.47%，全厂门对单车型不敏感，故 YM33J- 改善幅度以车型门为准）、全厂不劣化核对（8.08%/9.79% 双基线）。
6. **工期**：1 天任务包在既有框架（01_learn_takt 模板 + eta_v2 小模块）下可行，但三段回归对拍（W1 回放 + W2 回放 + W3 影子，各 ~30-60min）应显式留在排期内，防"合流日"挤爆。
