## 三、修复方案 (α)（我的设计，请审核其正确性/最小性/遗漏）

**R3'（Doc14 §5 语义修订 v1.4 候选）**：139='1' 且「自最近一次 raw-1 事件后未过
25IS010/25IS110/25IS210」→ '1'；否则 → '0'。= 把离线净化窗语义（已拍板 D1）镜像回在线状态机。

**实现设计**：
1. `VehicleState` +1 字段 `loop_exit_since_raw1: bool = False`（缺省 = 旧语义）。
2. 池状态更新（`_ingest_core` 在池分支 + 收养分支）：
   - 事件 raw 139='1' → 置 False（新 raw-1 起窗）；
   - 事件站 ∈ {25IS010,25IS110,25IS210} → 置 True（出环）；
   - R3 泛化（再过入口站 = 新周期）→ 重置 False；
   - 收养（不在池）→ 按收养事件初始化（raw-1 → False；25IS 三站 → True；余 False = 与现状同）。
3. `resolve_effective_flag` +1 可选参 `loop_exited_after_raw1: bool = False`：R3 分支改为
   `if flag139 == '1': return '0' if loop_exited_after_raw1 else '1'`；缺省 False = 旧语义
   （DUAL_RING=0 回滚路径、既有 37 例单测、静态 effective_flag 直通均不受影响）。
4. `estimate_event_unified` +1 同名可选参透传（缺省 False）；`predictor.rem_of` 传
   `v.loop_exit_since_raw1`。
5. 不改：学习表（零重学）/ 静态路径（effective_flag 直通）/ W4.4b G2 数字（static）/
   37 站 R1 / R2 黑顶三防 / 旧引擎。

**边界考虑（请重点复核）**：
- (a) 返修再入环：出环 True 后再遇 raw-1 → 置 False 重新入窗（与净化窗「首 raw-1」语义一致？

  二次返修车的净化语义本身有歧义，我的设计 = 按"最近一次 raw-1"起窗，在线侧自洽但可能
  与静态侧二次返修车不完全一致——量级？可忽略？）
- (b) 黑顶 '2' 是否需要同样的出环守卫？R2 已有 oven 三防 + BLACKTOP_ONLINE_WHITELIST
