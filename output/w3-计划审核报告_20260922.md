**阻断/待改**
- **B3（阻断）数据新鲜度护栏缺失**（见 §1）：须加全局心跳 `max(now − 事件时间) > 30min → 数据陈旧态`：冻结停线/缺口告警、看板显示「数据陈旧」横幅、恢复后自动解冻并记日志。这是 Task 2 的一等公民，不是事后补丁。
- **B4（阻断）冷启动 bootstrap —— 方案已定稿（2026-09-22 Q&A 决策）**：
  在制池是内存数据结构（以车身号 BODY_ID 为键的字典），进程一重启即清空；而现场任何时刻有 ~1000 台车在制（实测 873–1,075）。不补回则重启后预测系统性偏低（漏掉缓冲/烘房/返修中「数小时不过扫码器」的几十台车，量级 ~3pp，直接侵蚀 ±10% 验收门）。定稿方案：
  1. **回放重建**：启动时拉取 `carbody_history` 最近 120h 事件（~20 万条），按时间顺序喂给与在线**同一个状态机**（复用回放游标既有代码路径与测试，不建第二套重建逻辑）；秒级完成；回放数据流过即弃，只留池；
  2. **窗口 = 死车阈值**：120h 回放窗口与 120h 死车阈值同值（120h > 单程跨度 P90 70.2h，长尾由收养/死车兜底），口径自洽，一个数两个用途；
  3. **中途收养规则**（在线与 bootstrap 都生效的通用规则）：不在池里的车一旦出现新事件 → 立即收进池（位置=事件所在站，状态=事件 flag），覆盖长滞留车（>120h）、ETL 断流后回填、池移除后再进站三类边界；
  4. **无本地状态文件**：状态完全由「事件流 + 回放」重建，首次启动与崩溃重启同路径；`dss.work_pool_snapshot` 为可选审计留痕，**不是运行依赖**；
  5. **启动交叉核对**：回放建池后与 `dim_vehicle_profile`（在制产品车快照）核对车集合，差集应接近零，差异记日志（实测两者口径一致：~900–1,000 台）；
  6. **启动顺序**：读周计划 → 加载 `dss.dim_*` 学习表（库内常驻，重启不丢）→ 回放 120h → 交叉核对 → 打印启动报告（池大小/分段/flag 分布/数据截至时间/生效配置）→ 跑 B3 新鲜度检查（启动时数据已陈旧则立即宣告「数据陈旧」，不假装最新）；
  7. **env 可配**（2026-09-22 DSS_* 拍板落地）：`DSS_BOOTSTRAP_HOURS`（默认 = `DSS_DEAD_VEHICLE_HOURS` 的值，保持两值绑定）、`DSS_DEAD_VEHICLE_HOURS=120`；重启生效，启动报告打印生效值；测试可压缩阈值快速单测边界行为。
- **B7 关联（见 Task 5）**：关键站清单是模式 A 的硬依赖，Task 2 的池状态应能支撑（按站最近事件时间暴露）。

**中等项**
- **M4 乱序/迟到事件语义缺失**：ETL 存在回填（W1 备注：09-21 一次回填 ~+17k 事件）。定义 skew 窗口（建议 15min）：窗口内事件幂等合并（以该车事件日志重算单车状态）；更旧事件进审计日志。增量消费建议用 **ID 水位**（`ID` 为数字，`meta.refresh_watermark.ods.carbody_history.max_id` 现成）+ 每日全量核对（近 7 天）。
- **M5 flag 值域扩展**：DB 实测除 0/1/2 外存在 `'-'`（4,298 事件，0.07%）与 `'3'`（2 事件，上下文 `'113--'`/`'1130-'`）。W1/W2 学习时排除，在线状态机语义必须定义：**无效 flag → 继承最近一次有效 flag，不得复位为 0**——否则返修车经过未打标站会被误判回主线分流。
- **M6 多次进/出站语义未写**：DB 实测二次进站 66 车（0.08%）、二次出站 24 车（0.03%），最高 3 次。建议：首次出站 = 池移除；二次进站 = 新周期重新入池（flag 状态机重置为该周期的有效值）；多余出站审计计数。

  2. **分母（基准）必须定义正确**：计划只说「标称 P50 节拍」，未指明谁的 P50。**正确 = 模型训练基准（历史 P50 节拍，同班次型、条件允许同时段窗）**——模型本身就按历史学，α 的语义是「今天 vs 历史」；若用「计划目标隐含节拍」做基准，最典型的大生产日恰好失效：计划 920 vs 历史 700、现场真跑出 920 → 计划基准 α=1（不修正），但按历史学的模型需要 700/920 的修正——**最需要修正的日子漏修正**；且常规日会把「计划定得激进/保守」误读成「现场慢/快」，把预测往计划上拽、掩盖缺口告警 Δ 本应显示的缺口（计划激进度是 Task 4 的 Δ 的事，不是 α 的事）；
