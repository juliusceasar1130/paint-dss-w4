### M1｜⑥a 净化 SQL 语义：注释「前环人群」≠ 实现「最后环之前」

- **位置**：L866-867（注释）vs L881 / L895（条件）
- **证据**：
  - 注释：`p 只从前环人群学（flag=0 且该车该事件之前无 flag 1/2 事件）……排除"环后回主线"车`
  - 实现（两分支同）：`AND (e.last_loop_t IS NULL OR e.t < e.last_loop_t)`；`last_loop_t = max(t) FILTER (WHERE flag IN ('1','2')) OVER (PARTITION BY body)`（spike_w1/sqlbase.py）= **最后**环时间
  - 差异仅在多环车（≥2 环）："环 1 之后、环 2 之前"的 flag=0 事件（正是"环后回主线"样本）满足 `t < last_loop_t` → 进分母；而分子用 `f1 > e.t`（**首次**环，L876）→ 这些事件被记作"未来不进环" → p 被污染（系统性低估）。单环车两者等价
- **修复建议（W2 内自算，不动 W1）**：WHERE 改为「首次环之前」：
  ```sql
  AND (f.f1 IS NULL OR e.t < f.f1)
  AND (f.f2 IS NULL OR e.t < f.f2)
  ```
  （f1/f2 = `min(t) FILTER (WHERE flag='1'/'2')`，join 子查询已有；两处分支同步改）
- **联动**：修复后 `21IS565(2N54Y-)` 等格 p1/n 会变化 → L1162 本就要求观察 W2-S3 的 21IS565 断言，修订后首次运行重点看这条
- **可选**：sanity 增加"净化前后 p 对比抽样"（非必做）
