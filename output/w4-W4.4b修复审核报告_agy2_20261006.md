## 二、逐项审核点深度评判

### 审核点 1：修复正确性与边界（含 ND Retrofit 连带评判）

#### 1. 最小改动原则核查
在 `spike_w2/eta_v2.py::resolve_expected_delay` 中：
```python
def resolve_expected_delay(tables: dict, station: str, model: str,
                           mode: str) -> Optional[int]:
    table = tables.get("expected_delay") or {}
    for m in _model_tiers(model):
        row = table.get((station, m))
        if row is not None and row[2] >= DELAY_MIN_N and row[3] >= DELAY_MIN_N:
            return int(row[1])  # 两档均消费 delay_p50_s（W4.4b 2026-10-06）
    return None
```
- **判定**：**完全正确，系最小必要修改**。
- **机制验证**：保留了 `mode` 入参签名，保证了调用端契约（`estimate_event_unified` / `estimate_event_net_delay`）向后兼容；表内显式索引从 `int(row[0] if mode=='shift' else row[1])` 收敛为 `int(row[1])`，彻底拔除了 `delay_mean_s` 在所有在线预测与回放链路中的活跃消费。

#### 2. ND Retrofit 连带消费 p50 的语义可接受性
- **现状**：`estimate_event_net_delay`（仅用于 `DSS_DUAL_RING=0` + `DSS_USE_NET_DELAY=1` 组合）由于共享调用 `resolve_expected_delay`，其 delay 补偿也连带变更为消费 `delay_p50_s`。
- **判定**：**不仅语义可接受，而且在工程上完全正确、防止次生缺陷**。
  1. **避免回滚踩坑**：Retrofit 机制最初在 doc10 设计，旨在解决旧引擎 $p \times L$ 膨胀到 40h 的痛点。若在 Retrofit 中保留消费 `delay_mean_s`（12h~28h），一旦生产发生回滚切至该分支，仍将面临严重的阈值截断低估；切换至 `delay_p50_s`（2.6h~5h）与物理上真实返工延误的中枢完全一致。
  2. **回滚基线纯净性**：若运维需要纯正的“历史回滚口径”，只需设置 `DSS_DUAL_RING=0` 且 `DSS_USE_NET_DELAY=0`，代码将直接走 `estimate_event`（消费旧 $p \times L$ 与 `comp_excl`），回滚通道完全未受污染。

#### 3. 边界纪律审查（cc bp 反证实验）
- **边界纪律**：统一引擎内部 `rem` 与 `loop_rem` 的 shift 档列语义**坚决不改动**，维持消费 mean 列（`row[1]`）。
- **反证证据**：cc 独立执行的 bp 实验表明，若将内部 `loop_rem`/`rem` 连带改为 p50，全厂误差反而劣化至 **11.17%（符号偏差冲高至 +5.83%）**。因为进入环内的在制车本身已处于延误状态，环内剩余时间用 p50 补偿会导致低估在制残余耗时，引发反向的过计数。
- **审查结论**：修复严格隔离在 `expected_delay` 这一外部主线补偿项上，未外溢至内部基线与环表，边界纪律执行严密。

### 审核点 4：关账判定合理性（10.60% 超门 0.60pp 处理）

#### 1. 结构与噪声带宽深入分析
- **样本量约束**：Scene 3 排班输入独立回放窗（KW36/37）有效班次为 $n = 14$ 班。在 $n=14$ 的小样本下，单个边界班次的排产波动对中位误差的拉动步长为 **$\pm 0.3 \sim 0.5\text{pp}$**。因此 0.60pp 的偏差实质上处于统计度量噪声的物理带宽内。
- **分窗与分班形态**：
  - **稳态周 KW37**：全周中位绝对误差仅 **8.76%**（显著优于 10.0% 硬门）；
  - **中班工况**：全窗中位绝对误差仅 **7.91%**（显著优于 10.0% 硬门）；
  - **拖累集中点**：残差完全源自 **KW36 经历 09-06 停产检修后的两个恢复日（09-07 与 09-08 日班）**。停产重启初期存在的过站积压与暖线变节奏，是离线静态回放模型无法预测的物理客观现实。
- **全厂偏差归零**：符号中位偏差达到 **+0.71%**，证实模型预测中枢已无系统性偏倚。

#### 2. 低估风险与关账结法评价
- **风险评估**：若为了消弭这 0.60pp 而在静态回放侧针对 KW36 特殊微调参数，极易陷入过拟合。
- **先例与结法**：参考 W2.1 关账先例（全窗 14.16% 离线超标留痕，由在线自适应承接），本次 10.60% 超门如实留痕备案、将 0.60pp 残留转交 W3 在线 α 自适应调节器（吸收动态停产/恢复瞬态波动）是完全合理、科学且风险受控的关账路径。

### 审核点 5：其它潜在问题排查与定性

#### 1. F1：YM33J- 净化效应 +4.5pp（40.22% $\to$ 44.69%）
- **现象归因**：YM33J- 是全厂高返工车型。在 W4.1 净化规则下，烘房前的大量假 flag 1/2 被清洗为 flag 0。在旧引擎中，这些车凭借假 flag 提前享受了环内补偿；清洗后走纯净基线，但在后续真实入环率仍居高不下（>50%），导致在净化基线下轻微低估。
- **契约闭环**：doc10 §1.4 已有白纸黑字拍板：*“第一迭代不动环内通路，第一迭代验收不承诺返工车组改善（W2 误差主体在此路径）”*。
- **优先级判定**：**P2 跟踪项**。属于第二迭代（SCC 强连通分量切环）的既定治理目标，不构成 W4.4 关账阻断项。

#### 2. F2：251 格 $p_1 \ge 0.1$ 无 delay 行（覆盖缺口）
- **真库排查结果**：审核团队编写 SQL 探查了全表 2,198 个 $p_1 \ge 0.1$ 格子的实际解析路径：
  - 956 格命中精确车型行；
  - 510 格回退至平台前缀行；
  - 511 格回退至 `ALL` 兜底行；
  - **真正无任何层级覆盖（无车型、无前缀、无 ALL，静默回退 0.0）的仅 221 格，集中分布于 33 个工位**。
- **物理成因揭秘**：这 33 个工位全部为 **返修/黑顶环内工位**（如 `14IS120`、`24IS185`、`24IS115`、`24IS130`、`24IS060`）或烘房出口过渡工位（`18IS345`）。在这些工位上，真实流经且后续还会进环的“干净在制车”样本量极少（$N_{\text{clean}} < 30$），因而未生成 `ALL` 行；而真实进环车在在线引擎中统一走 **分支 A（环内 `loop_rem` 预测）**，根本不经过分支 B 的 `expected_delay`！
- **优先级判定**：**P3 观察项**。物理上无静默漏计风险，影响量级极小，按既定计划挂单补产覆盖率说明报告即可。

#### 3. 治理项：新引擎缺少独立的 Net Delay 开关
- **现状**：当 `DSS_DUAL_RING=1` 时，统一引擎恒调用 `resolve_expected_delay`，环境变量 `DSS_USE_NET_DELAY` 被忽略。
- **风险分析**：若在线阶段维表数据产生偶发污染，运维人员目前只能选择整机回滚至旧引擎（`DSS_DUAL_RING=0`），缺乏在新引擎内部单独剥离 delay 补偿的调试/容灾通道。
- **建议**：建议后续迭代补入 `DSS_EXPECTED_DELAY=0/1`（严格 1/0 校验），作为受控治理项登记。

#### 4. sc1 自学生成 13.22%（超线 3.2pp，比 sc3 差 2.6pp）
- **成因**：在独立窗（8 天 / 14 班）回放中，无外部排班表输入时，自学算法需从事件流时间戳推断班次跨度（10h 还是 11h）。因停产恢复期事件稀疏，算法在个别边界班次（如 09-08/09-11）推断存在 1 小时端点偏移，直接改变了 5h 锚点的截断线。
- **定性**：系短窗自学日历的固有结构性局限，已在 W2.1 形成共识，不代表核心预测引擎缺陷。
