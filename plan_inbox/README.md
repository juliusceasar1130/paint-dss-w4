# plan_inbox — 周计划输入监听文件夹

> **拍板（2026-09-23）**：周计划固定文件夹 = 项目内本目录（开发默认路径）。
> 生产环境（内网部署机）的路径用 `.env` 的 `DSS_PLAN_FOLDER` 覆盖，目录本身不变。

## 放什么

每周的生产计划文件（形式 1：标准 CSV / Excel），**文件名建议**：

```
week_plan_<年份>KW<ISO周号>*.csv    例：week_plan_2026KW40.csv
```

- 列格式见 `docs/08-周计划与排班输入数据规范.md`（6 列：`日期,日班工时,中班工时,出车计划,进车计划,备注`）
- 工时取值 `8 / 10 / 11 / 休`（休 也可填 `0` 或留空）
- 日期 `YYYY-MM-DD` 或 `M/D` 均可

## 本目录现有文件

| 文件 | 说明 |
| :--- | :--- |
| `week_plan_2026KW40_sample.csv` | **示例数据（KW40 = 09-28~10-04）**，量级取自历史典型周（11+11 ≈ 920–980 / 11+10 ≈ 770–795 / 周日休）。真实周计划到位后**直接覆盖或替换**，解析器不认 `_sample` 后缀，认的是命名与列结构。 |
| `week_plan_2026KW36.csv` / `week_plan_2026KW37.csv` | **09-05~09-13 实排班载体**（用户提供 KW36/37 排班截图提取，2026-09-23 P4 自 `scratch/02_replay_kw37.py` SCHED 字典转出）；出车计划列 = 实测回填（4 出口并集去重、中班尾归前一日，**非原计划值**）——仅用于 M9 回放窗 + T1 解析器验证，**不用于 Δ 对账**。 |

## 监听规则（Task 1 目录监听 M3 实现时生效）

1. 新文件出现 / 既有文件更新（mtime 变化）→ 解析入库 `dss.dim_weekly_plan`
2. 解析失败 → 不阻塞系统，报「计划解析失败」提示（B2 后仅 CSV/Excel 两种形态，OCR 已移除）
3. 某周无计划文件 → fallback 事件流自学模式（docs/08 三·3），服务不中断
4. 历史文件保留不删（审计 + 回放用）

## 给真实数据的两种方式

- **直接放文件**：把周计划 CSV/Excel 丢进本目录即可
- **聊天发数据**：把计划文本发给 agent（docs/08 形式 2 的聊天格式也行），由 agent 按规范转成 CSV 放入本目录并核对
