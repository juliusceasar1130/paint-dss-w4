## 阶段 0：公网准备（半天）

1. **打包代码**：git 仓库（`main`，含到 commit `6a6eba8` 的全部）拷贝到内网可达介质。
   必需内容：`spike_w1/ spike_w2/ spike_w3/ tests/ plan_inbox/ environment.yml .env.example`（`scratch/`、`output/snapshots/` 不用带）。
2. **验收周计划**：按 `plan_inbox/README.md`（docs/08 规范）生成验收周的
   `week_plan_YYYYKWww.csv`——**必须是真实前瞻计划（非实测回填）**：M5 的 ±10% 门考的就是"计划 vs 实际"。

## D0：内网部署（半天，checklist 逐项打勾）

```bat
:: [1] 装环境（机器无 miniconda 则先装；environment.yml 已固化版本）
conda env create -f environment.yml

:: [2] 配 .env（只改 4 处，其余全部保持默认——默认即生产口径）
copy .env.example .env
```

`.env` 只改这 4 行（其余注释掉或保持默认）：

| 键 | 值 | 说明 |
|---|---|---|
| `DSS_DB_HOST` / `DSS_DB_PORT` / `DSS_DB_NAME` / `DSS_DB_USER` / `DSS_DB_PASSWORD` | 内网生产库 | 账号需 `dss` schema 的 CREATE 权限 + `ods` 层 SELECT 权限。**M5 准备 agy 阻断 F1 已修：`DSS_DB_*` 现真正被连接层读取**（spike_w1/spike_w3 全链路生效；此前代码硬编码 127.0.0.1，这 5 行改了也不生效） |
| `DSS_PLAN_FOLDER` | 生产计划目录 | 把验收周 CSV 放这里（文件名规范见上） |
| `DSS_RUN_TAG` | `m5` | 5 天快照进同一目录 `output/snapshots/m5/`，收账方便。**显式 tag 重启幂等追加同目录**（agy 阻断 F3 已修：不再落 -r2 割裂快照；文件名自带时间戳不冲撞） |
| （可选）`DSS_SNAPSHOT_DIR` | 保持默认 `output/snapshots` | |

**不动的默认值（都是生产口径，改了 = 验收作废）**：`DSS_CLOCK_MODE=wall_clock`、`DSS_POLL_INTERVAL_SEC=300`、`DSS_STALE_MIN=30`、`DSS_ALPHA_MODE=off`、`DSS_ALERT_RED=-0.10`、`DSS_ALERT_YELLOW=-0.05`、`DSS_ALERT_DEBOUNCE_MIN=10`、学习窗 2026-04-14→08-15。


## D1–D5：正式在线跑（一次启动，连续 5 天不停）

```powershell
# 在 PowerShell 窗口执行（自动重启循环：进程崩溃 30s 后自愈重启，状态由 120h bootstrap 重建；按天写日志）
New-Item -ItemType Directory -Force m5 | Out-Null
while ($true) { conda run --no-capture-output -n paint-dss python spike_w3\01_boot_online.py *> m5\log_$(get-date -f yyyyMMdd).log; Start-Sleep 30 }
```

**屏幕上每 5 分钟看到**：
- 状态行：`[MM-DD HH:MM] 池=… cross_check=… FRESH|STALE`
- 控制台帧（`[DSS]` 开头）：各活跃班次的 A / pred / 目标 / Δ / 红黄绿、最近确认告警、ETL 诊断
- 快照：`output/snapshots/m5/snap_YYYYMMDDTHHMMSS.json`（每轮一个，一天 288 个；**wall_clock 已做 5min 网格对齐 + 漂移补偿**——帧 ts 分钟恒为 :00/:05/.../:55，锚点帧可被 ±3min 容差匹配；首帧 = 启动时刻可能未对齐，后续帧自动对齐）

### 每日检查单（~10 分钟）

| 时间 | 动作 | 记录到哪 |
|---|---|---|
| 04:45 前 | 进程活着？（日志有新状态行；没有 → 看日志尾 + 重启循环是否工作） | 运行日志 |
| **日班锚点（随型：11h→10:00 / 10h→11:00 / 8h→13:00，常见 10:00）/ 21:30** | **抄当天两帧的 A / pred / 目标 / Δ / 灯色**（5h 锚点帧 = work_start+5h，验收核心；快照里有，手抄是双保险） | 锚点记录表 |
| 红/黄告警出现（`[DSS]` 帧有「确认」字样） | 记：时刻 + 班次 + 缺口台数 | 告警台账 |
| 状态行变 STALE（断流） | 记断流**起止时刻**（开始 = 首个 STALE 状态行；恢复 = 回到 FRESH）。**不杀进程、不动 ETL**（内网数据负责人处理，RTO≤1h） | 断流记录 |
| 次日 04:00 前 | 数当天快照：`dir output\snapshots\m5\ /b \| find /c "snap_2026-10-05"` 应 = 288 | 快照清单 |

| 日期 | 日班锚点（10:00/11:00/13:00 按型；A/pred/目标/Δ/灯） | 中班 21:30（A/pred/目标/Δ/灯） | 当日快照数 |
|---|---|---|---|
| D1 | | | |
| … | | | |

**告警台账**

| 时刻 | 班次(scope) | 转换（如 green→yellow→red） | 缺口台 | 事后核实（真缺口 or 误报） |
|---|---|---|---|---|

**断流记录**

| 起止时刻 | 时长 | ETL 侧原因（问数据负责人） | 期间是否触发 STALE 冻结横幅 |

## 收账判分（D5 结束后，1 小时）

```bat
conda run --no-capture-output -n paint-dss python spike_w3\04_m5_acceptance.py --snap-dir output\snapshots\m5 --dates <D1日期>,<D2日期>,...,<D5日期>
```

- 产出：`output/w3-M5-验收报告.md`（主表 + 断流统计 + 告警台账 + 终判）+ `output/w3-M5-验收.json`（机读）
- **多目录**：若启动过旧版/自动 tag 导致出现 `m5-r2` 等 -r 目录，`04` 会显式 WARNING 点名；确认属同一 M5 运行则重复传 `--snap-dir output\snapshots\m5 --snap-dir output\snapshots\m5-r2` 合并收账（同 ts 重复帧先入者胜，报告头部列重复数）。
- **主判据**：逐工作日 5h 锚点（**日班随班次型**：11h→10:00 / 10h→11:00 / 8h→13:00；中恒 21:30；锚点帧容差 ±3min）|Δ实际| ≤ 10%；Δ实际 = (pred − 实际终局)/实际终局；实际终局 = 4 下线点产品车闭区间计数（日 [04:45,16:30] / 中 [16:30,次日按型]，与 a_of `<=end` 同源）。
- **不计门（四桶互斥，报告分别计数）**：休日（自动剔除）、实际终局 0（停线/无事件，reason=actual_zero）、锚点帧 STALE（断流冻结，reason=stale）、锚点帧缺失（进程离线/缺帧/漂移超容差，reason=anchor_missing，显式留痕行）。
- **终判 PASS** = 计入门的每个班次行 |Δ实际| ≤ 10%。

**报告人工核对三件事**（脚本之外）：
1. 告警台账每行填「事后核实」：该缺口事后是否真实发生（真缺口 = 告警有效；未发生 = 误报）。
2. 断流时段与数据负责人的 ETL 故障记录对得上。
3. 快照数每天 = 288（缺帧 = 进程中断过，查对应日志）。

**验收报告归档**：`output/w3-M5-验收报告.md` + 三份记录表 + 关键日志节选 → 回公网后 agent 协助整理成正式验收报告（或内网直接拍照/导出）。

## 排障速查

| 现象 | 第一反应 |
|---|---|
| 启动报「缺表」 | 学习表没建全（D0[3]）→ 重跑 01_learn_takt / 01_learn_v2 |
| 启动报周计划缺日 | 验收周 CSV 行不全 / 日期格式错 → 对照 plan_inbox/README.md 修文件，重跑 01（upsert 幂等） |
| 持续 STALE | ETL 断流（非本系统故障）→ 记时段，找数据负责人；恢复后自动解冻，期间不计门 |
| cross_check > 1% | 查启动报告明细（哪几台不一致）；若 bootstrap 数据本身有问题找数据负责人 |
| 进程反复重启 | 看 `m5\log_*.log` 尾部异常栈；常见 = 库连接断（重启循环会自愈）|
| 快照缺帧 | 对应时刻进程不在线（查日志）；缺帧时段在收账报告里体现为"锚点帧缺失"行 |
| 帧里「段=待确认」 | 85 个工位段名未补（M3 挂账）——不阻断，告警瓶颈定位显示「待确认」，M5 前补上更好 |
