# 涂装车间 DSS — 共享环境准备与首跑手册（v1.0，2026-10-11）

> **用途**：把本项目交给他人做学习/开发时，接收方从零到「学习 + 回放链路可跑」的完整准备。
> **共享包 = 两样东西**：① 本 git 仓库（代码 + 验证脚本 + 文档）——经 GitHub 私有仓库 clone，或直接打包 zip；② `dss_source.dump`（258 MB，PG 自定义压缩格式，2026-10-11 从导出方本地 `analytics_db` 快照导出，数据截止 **2026-10-09 15:27 Asia/Shanghai**，不进 git、单独传输）。
> **隐私边界（对接收方透明）**：仓库含 `plan_inbox/` 真实周计划 CSV 与 `output/` 实测报告（业务数据）——仅限公司内/受信接收方；对外共享时按 §6 脱敏并排除这两处。
> **不含**：`dss.*` 学习表（学习器自建）、周计划 CSV（业务数据、可选）、内网 ETL 实时链路（只有内网有）。

## 1. PG 数据库准备（约 10 分钟）

**版本要求**：PostgreSQL ≥ 13（导出方实测 17.7；`-Fc` 自定义格式要求恢复端版本 ≥ 导出端，老版本 PG 恢复不了）。

```bash
# ① 建库
createdb analytics_db

# ② 建 schema（pg_dump -t 不带 CREATE SCHEMA 语句，必须先建）
psql -d analytics_db -c "CREATE SCHEMA ods; CREATE SCHEMA dim; CREATE SCHEMA meta;"

# ③ 恢复（dss_source.dump 在共享包根目录）
pg_restore -d analytics_db dss_source.dump

# ④ 校验（5 张表行数须与下表一致）
psql -d analytics_db -t -c "
SELECT 'carbody_history '||count(*) FROM ods.carbody_history
UNION ALL SELECT 'dim_vehicle_profile '||count(*) FROM dim.dim_vehicle_profile
UNION ALL SELECT 'rb_position_data '||count(*) FROM ods.rb_position_data
UNION ALL SELECT 'sync_job_log '||count(*) FROM meta.sync_job_log
UNION ALL SELECT 'refresh_watermark '||count(*) FROM meta.refresh_watermark;"
```

期望输出：

| 表 | 行数（2026-10-11 基线） | 用途 |
|---|---|---|
| `ods.carbody_history` | 7,166,865 | 唯一学习/预测数据源（全部学习器 + 回放 + 在线流） |
| `dim.dim_vehicle_profile` | 94,826 | B4 bootstrap 交叉核对参考集（**缺表直接崩；空表只出 warning**） |
| `ods.rb_position_data` | 2,748 | B3 四信号诊断 S4（仅 wall 在线模式） |
| `meta.sync_job_log` | 26,485 | B3 诊断 S1：ETL 同步任务签到（仅 wall） |
| `meta.refresh_watermark` | 7 | B3 诊断 S2：ETL 水位（仅 wall） |

**dump 里不带的表（不需要，原因）**：

- 库里的其他 `ods.*` / `src_*` / `dim.carbody_registry` / `dim.dim_process_area` 等 —— DSS 代码完全没碰。
- `dss.*` 学习表 —— 学习器脚本自动建（`01_learn_takt.py:22` 含 `CREATE SCHEMA IF NOT EXISTS dss`，所以 `dss` schema 不用预建）。
- 周计划 CSV —— 非数据库内容，见 §5。

**连接账号**：任意有 `analytics_db` 读写权限的用户均可，不必叫 `root`（dump 已加 `--no-owner --no-privileges`，无属主绑定）。代码侧凭 `.env` 的 `DSS_DB_*` 五件套配置（见 §2）。

## 2. 代码侧环境（约 5 分钟）

```bash
# ① conda 环境（environment.yml 已固化）
conda env create -f environment.yml      # 环境名 paint-dss

# ② 参数配置（.env 不入库，用模版）
cp .env.example .env
# 编辑 .env：至少确认 DSS_DB_HOST / DSS_DB_PORT / DSS_DB_NAME / DSS_DB_USER / DSS_DB_PASSWORD
```

其余 `DSS_*` 参数（驱动模式、新鲜度阈值、α、预警线等）保持默认即可，调试时再改（规范见 `AGENTS.md` 与 `.env.example` 注释）。

**时区纪律**：所有时间/班次查询必须 `SET TIME ZONE 'Asia/Shanghai'`（会话默认 UTC，工厂时 = UTC+8）。`spike_w1/common.py:connect()` 已自动执行该语句，脚本无需操心；**自己手写 SQL 连库时必须手动设置**。列名大写需双引号（`"DATE_EVT"` / `"BODY_ID"` / `"MDS_DATA"` …）。

## 3. 首跑顺序（学习 → 回放 → 测试）

在仓库根目录，按序执行（Windows 下用 `conda run --no-capture-output -n paint-dss python <脚本>` 启动连库脚本，不依赖 shell 激活状态）：

| 步 | 命令 | 产出 / 判读 |
|---|---|---|
| 1 | `python d0_check.py` | DB 连通 + `dss` 表盘点（此时 dss 应为空）。**注意**：`ETL 时差` 会显示为 ~2 天（数据截止 10-09 15:27，快照不续更）——**这是公网快照的预期行为，不是异常**；「>30min 别开跑」判读只对内网实时链路适用 |
| 2 | `python spike_w1\01_learn_takt.py` | 建 6 张 `dss.dim_*` 学习表（默认学习窗 2026-04-14 → 2026-08-15）。跑完打印各表行数与自校准指标 |
| 3 | `python spike_w2\01_learn_v2.py` | 建 6 张 `dss.v2_*` + `dss.dim_expected_delay`（+ 可选班次型档），并做班次级回放（默认回放窗 2026-08-16 → 2026-09-19），打印 D1' 门判 |
| 4 | `python -m pytest`（仓库根，全套件 470 用例） | 应全绿。唯一例外：`tests/test_db_smoke.py` 断言真实库快照（flag 分布 / 站计数）——若数据快照换过版本会过期，按维护惯例刷新断言值（`AGENTS.md`） |
| 5 | `conda run --no-capture-output -n paint-dss python spike_w3\02_shadow_replay.py` | M9 影子回放（replay 模式，时间穿透）：168h bootstrap + 120h 回放 + 逐 5min 滚动预测 + 5h 锚点 G2 偏差。这是离线验收的主链路 |
| 6（可选） | `python spike_w3\03_alert_backtest.py` | M10 告警回测（红黄绿缺口告警的历史行为复盘） |

**Windows 运行坑（已踩实）**：

- 连库脚本一律 `conda run --no-capture-output -n paint-dss python <脚本>` 启动；直调环境解释器出现过 `psycopg2.connect` access violation（0xC0000005，非必现）。
- `conda run -c "多行代码"` 报错（不支持含换行参数）——`-c` 仅限单行，多行写 scratch 脚本文件。
- 回放/门判脚本按约定 FAIL 时 `exit 2`，`conda run` 会跟一行 `ERROR conda.cli...` ——属上报约定，以产物文件为准。

## 4. 两种驱动模式：replay vs wall（决定你能跑什么）

| | **replay_cursor（影子回放，离线）** | **wall_clock（在线实时）** |
|---|---|---|
| 时钟 | 历史事件游标穿透（`now` = 回放位点） | 墙钟轮询增量流（5min 周期） |
| 依赖数据 | 仅 `ods.carbody_history`（+ `dim.dim_vehicle_profile` 交叉核对） | 额外读 `meta.*` / `ods.rb_position_data`（B3 四信号诊断） |
| 周计划 | 回放窗内计划，缺了兜底自学 | 前瞻周计划（必须真实计划，非回填） |
| 在公网能跑吗 | **能，且是学习/离线验收的主链路** | 进程能起，但 `meta.sync_job_log` 无新鲜签到 → B3 必判 STALE 熔断冻结——**公网无意义，留内网** |
| 入口 | `02_shadow_replay.py` | `01_boot_online.py`（内网 5 天验收手册见 `docs/09`） |

## 6. 数据红线与隐私（务必遵守）

1. **只读原则**：`ods` / `dim` / `fct` / `mart` / `meta` 层任何表与视图只读；本项目产物只写 `dss` schema（dss 内可 DROP + CREATE）。
2. **学习窗口纪律（C13）**：学习窗固定 2026-04-14 → 2026-08-15，回放窗自 2026-08-16 起——样本内外分离，别用回放期数据「训练」后回测。
3. **结构依赖，禁合成数据**：学习器硬编码产品车口径 `"BODY_ID" LIKE '78202%'`、259 站拓扑、`MDS_DATA` 电报 137/139 位标志位（位语义见 `README.md` 口径表、`docs/18`）。拿合成/别厂数据跑，验收门（W1 ≤30min 单车 / W2 ±10% 班次 5h）与全部机制验证失效。
4. **隐私**：`BODY_ID` = 车架号（VIN 前缀 78202），`MDS_DATA` = 237 字符电报（含滑撬号、车型、标志位，映射见 `docs/18`）。**公司内部共享可原样；对外共享必须脱敏**——对 `BODY_ID` / `SKID_ID` 做确定性重映射（保留前缀长度、关联关系与标志位语义），电报其余字段视密级处理。

## 7. 数据快照更新（导出方重导 / 接收方换库）

数据截止随源库同步（源库在车间内网，公网不自动续更）。换新快照时：

**导出方**（本机，pg 客户端在 `120JPH_postgres` 容器内）：

```bash
docker exec 120JPH_postgres pg_dump -h 127.0.0.1 -U root -d analytics_db \
  -t ods.carbody_history -t dim.dim_vehicle_profile \
  -t ods.rb_position_data -t meta.sync_job_log -t meta.refresh_watermark \
  --no-owner --no-privileges -Fc -f /tmp/dss_source.dump
docker cp 120JPH_postgres:/tmp/dss_source.dump <输出目录>/dss_source.dump
```

**接收方**（干净换新，不原地覆盖旧库）：

```bash
createdb analytics_db_new && psql -d analytics_db_new \
  -c "CREATE SCHEMA ods; CREATE SCHEMA dim; CREATE SCHEMA meta;"
pg_restore -d analytics_db_new dss_source.dump
# 换 .env 指向新库 → 重跑 §3 步 2–3（学习表全部重学）→ 步 4 校验测试
# 旧库确认弃用后再自行删除
```
