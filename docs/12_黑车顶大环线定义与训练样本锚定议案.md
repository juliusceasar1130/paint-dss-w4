## 1. 摘要与议案背景

### 1.1 核心问题
在涂装车间决策支持系统（DSS）中，黑车顶二喷大环线（Loop 2）是造成车身在制时间离散、影响班次产量达成预测（模块②）的关键工艺环。

当前离线学习器（`spike_w1/01_learn_takt.py`）对于黑顶环起点的界定采用朴素逻辑：
$$\text{Loop Start} = \min(t) \quad \text{WHERE } \text{flag}_{139} = '2'$$

**该逻辑存在严重的样本污染缺陷**：
1. **单色车闪现污染（G0 群体）**：全厂 4,941 辆单色车（`137=0`）在一喷进喷房（`14IS260 / 13IS260`）排队时，存在持续中位数 4.8 分钟的临时调度信号 `139=2`，闪现段虽 100% 迅速复位，但朴素抽取将其计入环时长，导致现行 `dss.dim_loop_duration` 的 `ALL flag2` 行被拉出 **P50 = 4.9h** 的无物理意义虚假插值峰。
2. **黑顶车假首发污染（受害组 536 辆）**：黑顶车（`137=1`，G1 共 5,877 辆）中有 **536 辆（占 9.1%）** 首个 `139=2` 提前落在 `14IS260`（`13IS260` 另有 45 辆，缓存线合计 581 辆）。导致算法将其一喷排队时刻错误当成二喷大环起点，**使受害车辆环时长中位数虚增 3.38 小时、均值虚增 9.28 小时（长尾达 203.8 小时，43 辆车 $\ge 24\text{h}$）**。

### 1.2 议案目标
本议案基于全量数据实证，确立以**“方案 A（面漆烘房出口前置锚点）为主主锚点、方案 B（后缀逆推）为备用兜底、方案 C 为在线防护”**的基准体系，彻底净化黑顶大环线训练集。

### 2.2 物理铁律：三座面漆烘房的不可逾越性与例外注记
在涂装物理工艺中，底漆必须在**高温面漆烘房（Topcoat Bake Oven）**完成交联固化并冷却后，才具备贴遮蔽纸、二次喷涂黑色车顶的物理条件。

车间共有 **3 座并行面漆烘房**，读写站全量映射如下：

| 烘房代号 | 归属工艺线 | 烘房入口读写站 | **烘房出口读写站（有效门槛）** | 内部测温点 | 历史过车总量 | 首座烘房经过黑顶车数 |
|:---|:---|:---|:---|:---|---:|---:|
| **L3FCC1** | 面漆1线烘房 | `16IS200` | **`16IS305`** | `16IS270`, `16IS285` | 9,617 辆 | 926 辆 |
| **L3FCC2** | 面漆2线烘房 (主线) | `17IS200` | **`17IS305`** | `17IS270`, `17IS285` | 87,239 辆 | 5,657 辆 |
| **L3FCC3** | 面漆3线烘房 | `18IS225` | **`18IS345`** | `18IS325` | 7,717 辆 | 275 辆 |

> **物理铁律**：在通过上述任意一座面漆烘房**出口站**之前，车身上发生的任何 `139=2` 绝对不是真正的黑顶二喷大环线起点。  
> **例外说明**：实测发现有 28 辆车（占受害组 4.8%）首段 2 贯穿烘房未复位（疑为一喷即喷黑顶底色的特殊车身）。方案 A 严格以**烘房出口站之后**作为判定基准，可将残余偏差压缩在 0.5% 以内。

## 3. 议案推荐方案架构（主次明确）

### 方案 A（离线训练唯一主锚点）：物理烘房出口前置约束法
以**“必须满足 `137=1` 且出面漆烘房出口站”**作为大环线的物理门槛。覆盖率达 **98.9%（5,813 / 5,877 辆）**，物理归位率达 **99.0%**（报交簇 88.1% + 打磨返修线 10.8%）。

```sql
WITH first_oven_exit AS (
    -- 1. 严格取每车首次离开三座面漆烘房出口站的时间戳 (t_oven_out)
    SELECT 
        "BODY_ID", 
        MIN("DATE_EVT") AS t_oven_out
    FROM ods.carbody_history
    WHERE "BODY_ID" LIKE '78202%'
      AND "RW_STATION_ID" IN ('16IS305', '17IS305', '18IS345', '20IS010')
    GROUP BY "BODY_ID"
),
blacktop_true_loop AS (
    -- 2. 必须具备 137=1 属性，且在出烘房后首次打上 139=2 的事件
    SELECT 
        h."BODY_ID",
        h."DATE_EVT" AS loop_start_t,
        h."RW_STATION_ID" AS loop_start_stn,
        ROW_NUMBER() OVER (PARTITION BY h."BODY_ID" ORDER BY h."DATE_EVT" ASC, h."ID" ASC) AS rn
    FROM ods.carbody_history h
    JOIN first_oven_exit o ON h."BODY_ID" = o."BODY_ID"
    WHERE h."BODY_ID" LIKE '78202%'
      AND SUBSTRING(h."MDS_DATA" FROM 137 FOR 1) = '1'  -- ★ 绝对必须：坚决排除 4941 辆 G0 闪现车
      AND SUBSTRING(h."MDS_DATA" FROM 139 FOR 1) = '2'
      AND h."DATE_EVT" >= o.t_oven_out
)
SELECT "BODY_ID", loop_start_stn, loop_start_t
FROM blacktop_true_loop
WHERE rn = 1;
```

### 方案 B（降级为备用兜底与质检校验）：清洁后缀逆推法
- **降级原因**：独立实测证实方案 B 存在 **5.3% 结构性失效**：
  1. 112 辆车（1.9%）在出站后站 `09IS360` 读到 0 复位，导致最后非 2 之后无事件（**产生 NULL 锚点**）；
  2. 199 辆车（3.4%）在环内发生返修打上 `139=1`，切断了 2，导致 B 取了最后一段 2（**环时长被系统性低估 16.16 小时**）。
- **定位**：**坚决不作为训练主锚点**。仅用于补齐方案 A 漏失的 8 辆无烘房事件车，以及离线质量对拍校验。

---

### 方案 C（在线推断实时防护）：白名单准入与前置黑名单抑制
在线流式服务（无法窥探未来烘房）通过物理围栏双向防护：
1. **环线准入白名单（已补齐打磨线）**：
   ```python
   BLACKTOP_ONLINE_WHITELIST = {
       # 报交入口簇 (占 88.1%)
       '24IS185', '24IS115', '22IS170', '23IS170', '23IS110', '22IS110',
       # 返修/打磨线簇 (实测占 10.8%，含 13/15IS 补漏)
       '14IS120', '14IS065', '13IS065', '15IS065'
   }
   ```
   仅当车辆处于上述白名单站点时，`139=2` 才激活黑顶大环线预测补偿。
2. **前置抑制黑名单**：
   若车辆在 `14IS260 / 13IS260` 读到 `139=2`，但此前未曾经过任何报交线（一喷前排队），引擎**强制静默抑制为 0**，按正常一喷主线计算。

```sql
-- 【复核点 1 (已修 Bug)】：验证 G0 单色车闪现段事件数 <= 2 的占比 (预期 >= 99%)
WITH flag2_0 AS (
    SELECT "BODY_ID", 
           COUNT(*) FILTER (WHERE SUBSTRING("MDS_DATA" FROM 139 FOR 1) = '2') AS cnt_2
    FROM ods.carbody_history
    WHERE "BODY_ID" LIKE '78202%' 
      AND SUBSTRING("MDS_DATA" FROM 137 FOR 1) = '0'

    COUNT(*) AS total_g0_cars,
    COUNT(*) FILTER (WHERE cnt_2 <= 2) AS short_flash_cars,
    ROUND(COUNT(*) FILTER (WHERE cnt_2 <= 2)::NUMERIC / COUNT(*) * 100, 2) AS pct

-- 【复核点 2 (已修标签)】：验证首发 14IS260 的黑顶车数量 (实测严格等于 536 辆)
WITH first_2 AS (

    FROM ods.carbody_history

)
SELECT f_stn, COUNT(*) FROM first_2 GROUP BY f_stn ORDER BY COUNT(*) DESC LIMIT 5;
```
